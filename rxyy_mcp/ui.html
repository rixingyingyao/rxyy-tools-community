zhi 每等这么久自动续期一次躲 Cursor 超时；IDE 用 300，CLI 用 45；0=关闭

        

        
技能与项目规则已从 Cursor 的常驻注入里搬进资料库，报到那一轮不带（省 token）。勾上后：点「开始任务」或第一次派活时附上用户规则+本仓指针全文（含已为省报到改成 .off 的文件），同一对话只发一次。技能仍给目录，命中再 Read。用 scripts/_library_setup.py 建库与还原

        

        
发给 agent 的那段规则会进系统提示词，每个窗口每一轮都要付。默认精简版约 365 token/请求（完整版 1237，砍七成），条款一条没少、只是不再解释来龙去脉。若某个模型不照做（不用 zhi 收尾、收到保活就收尾），勾上退回完整叙述版；改完下次 Cursor 重连该窗口生效

        

        
新会话报到/点「+」时叫醒等待中的 agent 续期一次「腾并发槽位」。已实测 Cursor 对同一 MCP 无并发上限（8 个 zhi 挂着时新调用 2ms 应答），此举只会让待命 agent 白跑一轮，故默认关闭；若再出现「同时开多个新对话进不来控制台」，勾上即恢复旧行为

        

        

        
控制台 tab ← Cursor 自动标题的周期（方向是 IDE→控制台）；0=关闭。反方向（控制台 → Cursor 侧栏）不归它管，见下面那个按钮

        

        
侧栏顶着「Persistent plus …」是因为写盘赢不了内存：对话还开着时 Cursor 会把内存那份刷回磁盘、连名字一起盖回来。这个按钮走 Cursor 自己的 composer.renameChat 命令（临时插一条快捷键→按下→把名字敲进输入框→还原 keybindings.json），当场改内存，侧栏立刻变，不用重启也不用 Reload Window。会抢一两秒键盘焦点，按之前先把手从键盘上挪开；只改控制台有把握的那些（agent 自报过真名或你锁过名字的）

        

        

        
勾上后上面那个按钮的活由控制台自己干。优先走注入桥（内存改名，不抢键盘）；桥没心跳才等到你连续这么多秒没碰键盘鼠标、且 Cursor 在前台时走键盘兜底。同一个名字 10 分钟内只按一次。
